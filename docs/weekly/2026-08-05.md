## 1. Monitoring, starting with Traefik

I began building dashboards for the services running on the cluster. Traefik came
first because every request passes through it, so it is the natural place to see
what is going on.

There was friction early on. Traefik was not tracked by ArgoCD, since it came bundled
with K3s, so building the dashboard also meant moving Traefik's configuration into the
repo. Doing both at once made it hard to tell which change caused which problem.
Looking back, bringing Traefik under ArgoCD was probably not what caused the issues,
but mixing the two jobs did not help.

The good outcome is a reusable template: drop a dashboard's JSON into a ConfigMap in
Git, and it shows up in Grafana. The plan is to do the same for every critical piece
of infrastructure.

## 3. A new project: Penny

A good friend asked me to build something together. The idea is an app for private
tutors to manage payments and schedules. Right now most tutors track this over
WhatsApp and rely on trust, which is easy to abuse on both sides.

- **Frontend:** Flutter, so one codebase covers every OS and the web.
- **Backend:** Go, for throughput and to keep it easy to extend.
- **Design direction:** traceability, immutability and reliability.

Plenty of alternatives already exist. What should set this one apart is that
contracts and invoices are tamper-evident, with each one signed using hashes so
neither side can quietly change the terms afterwards. Skeletons for both the frontend
and the backend exist, and there is a lot left to do.
