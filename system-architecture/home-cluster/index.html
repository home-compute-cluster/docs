    Homelab Kubernetes Platform — Architecture

    A three-node K3s cluster running GitOps-managed services, with a split public/tailnet ingress model and Longhorn distributed storage. This document captures the network topology (how traffic reaches the cluster) and the internal cluster topology (how workloads, storage, and GitOps fit together).

    Domains: *.packetcraft.dev (public, via Cloudflare Tunnel) · *.lab.packetcraft.dev (tailnet-only) Source of truth: BarneyLaw/homelab-cicd-config (GitHub) → ArgoCD

    1. Node inventory

    Node Hardware IP Role Notable duties
    deus Lenovo M910q 192.168.1.250 K3s server (control plane) + always-on cloudflared, WireGuard, ArgoCD, Traefik pinned here; no Longhorn replicas (thermal)
    nebula i7-6700K desktop 192.168.1.248 Worker + always-on ZFS NAS (tank), Seafile (Compose), GTX 1080, Longhorn NVMe replica
    legion Laptop (battery removed) 192.168.1.249 Worker + always-on Longhorn SATA replica (/var/lib/longhorn-disk-sda), MetalLB VIP advertiser

    legion runs 24/7 — it is a permanent node, not a transient/WoL worker.

    Two ingress pipes, one brain. Cloudflare Tunnel (public, outbound-only, no open ports) and Tailscale/WireGuard (private) are dumb pipes. All routing logic lives in Traefik IngressRoutes. This is the single-routing-brain principle: per-app proxies are scoped to their own stack and never become a second general-purpose ingress.

    WireGuard (UDP 51820) private IPs — High-throughput admin path

    4. GitOps deployment flow

    The git push → build → deploy loop that stands up every built-from-source service.

    sequenceDiagram
    autonumber
    participant Dev as You (git push)
    participant App as app repo
    participant CI as GitHub Actions
    participant GHCR as ghcr.io
    participant Cfg as homelab-cicd-config
    participant Argo as ArgoCD
    participant K3s as K3s cluster

    Dev->>App: push to main
    App->>CI: trigger build.yaml
    CI->>GHCR: build + push image:SHA
    CI->>Cfg: kustomize edit set image → commit tag bump
    Note over CI,Cfg: fine-grained PAT (Contents: RW)<br/>CI has NO cluster access
    Argo->>Cfg: watch / detect new commit (~3 min poll)
    Argo->>K3s: reconcile Deployment to image:SHA
    K3s-->>Argo: Synced / Healthy
    Note over Argo,K3s: selfHeal reverts manual drift<br/>prune removes deleted resources

    Two-repo split. CI writes to the config repo; ArgoCD reads from it. They never talk directly — a single repo would loop (CI's write-back re-triggers CI). Off-the-shelf images (Grafana, Jellyfin) skip CI entirely: just an apps/<svc>/ manifest + ArgoCD Application.

    5. Key architectural principles

    • NAS owns data, K3s owns services. Seafile lives on Compose for data-safety; ZFS tank on nebula holds durable state. Jellyfin placement remains open (GPU is on nebula, a Compose host).
    • Cloudflare Tunnel = dumb pipe, Traefik = routing brain. All routing logic in IngressRoutes; ingress pipes just feed it.
    • Single routing brain. Per-app proxies stay scoped to their stack — never a second general-purpose ingress.
    • Longhorn cannot use ZFS. Needs a dedicated disk formatted ext4/XFS at a stable mount, multipathd blacklisted. 2 replicas = the floor for node-independent redundancy.
    • selfHeal + Helm-managed secrets = churn. Chart-owned credentials get reset on reconcile → migrate to existingSecret + SealedSecret.
    • Sealed Secrets key backup is critical. Losing the controller private key makes all sealed secrets unrecoverable.
    • Ansible below K3s, ArgoCD in-cluster. The two layers must not overlap.

    7. Known gaps & horizon

    Open drift / gaps - Grafana lab. IngressRoute still hand-applied → move to apps/monitoring-extras/ - Grafana admin password → SealedSecret migration pending - GitHub webhook for push-triggered ArgoCD sync not yet configured (currently poll-based) - Renovate not yet set up - code-server ambient credential leak fix deferred

    On the horizon - Portfolio site (static + Go API + Postgres) — first real app, before obsync - obsync (Go backend + Postgres, both in K3s) — deferred to avoid layering Go + Postgres + custom protocol at once - Control-plane HA — single-server etcd is a known SPOF; endgame is 2–3 dedicated mini-PC server nodes - Longhorn backup target — NFS share on nebula's tank, to configure before any DB holds real data
